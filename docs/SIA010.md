# SIA010 — `[UnionId("X", "Y")]` names types and should be `[UnionId<X, Y>]`

| Severity | Code fix | Applies with `dotnet format` |
|----------|----------|------------------------------|
| Warning  | Yes      | Yes |

Fires when every string tag of a `[UnionId(...)]` is the name of a type in scope at the attribute. `[UnionId<X, Y>]` carries the same tags, but the compiler checks them: renaming a type updates the attribute rather than leaving a stale string behind that silently stops matching.

This is [SIA009](SIA009.md) for `[UnionId]`.


## Example

```cs
public class Customer;

public class Order;

public class Note
{
    [UnionId("Customer", "Order")] // SIA010
    public Guid Subject { get; set; }
}
```

Build output:

```
SIA010: [UnionId("Customer", "Order")] on property 'Note.Subject' names the types 'Customer', 'Order'. Fix: replace it with [UnionId<Customer, Order>].
```


## How to fix

Replace the attribute with the generic form, keeping the tags in the order written:

```cs
[UnionId<Customer, Order>]
public Guid Subject { get; set; }
```

```
dotnet format analyzers --diagnostics SIA010
```


## When it does not fire

 * The project's `LangVersion` is below C# 11: generic attributes do not exist there, and the generic `[UnionId<...>]` forms are not emitted.
 * Any one tag names no type in scope at the attribute (a missing `using` counts), or names more than one.
 * Any one tag names a generic type (CS0305) or a static type (CS0718).
 * There is a single tag: that is [SIA006](SIA006.md), whose fix writes `[Id<X>]` directly.
 * There are more than five tags: the generic forms go up to `[UnionId<T1, T2, T3, T4, T5>]`.
 * The tags are passed as an array expression (`[UnionId(new[] { "X", "Y" })]`) rather than as separate arguments.
