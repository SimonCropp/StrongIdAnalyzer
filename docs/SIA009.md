# SIA009 — `[Id("X")]` names a type and should be `[Id<X>]`

| Severity | Code fix | Applies with `dotnet format` |
|----------|----------|------------------------------|
| Warning  | Yes      | Yes |

Fires when the string tag of an `[Id("X")]` is the name of a type in scope at the attribute. `[Id<X>]` carries the same tag, but the compiler checks it: renaming the type updates the attribute rather than leaving a stale string behind that silently stops matching.


## Example

```cs
public class ConfigEntry
{
    public string Id { get; set; }
}

public static class Queries
{
    public static Task<string?> Find(Db data, [Id("ConfigEntry")] string key) => ...; // SIA009
}
```

Build output:

```
SIA009: [Id("ConfigEntry")] on parameter 'key' of 'Queries.Find' names the type 'ConfigEntry'. Fix: replace it with [Id<ConfigEntry>].
```


## How to fix

Replace the attribute with the generic form:

```cs
public static Task<string?> Find(Db data, [Id<ConfigEntry>] string key) => ...;
```

```
dotnet format analyzers --diagnostics SIA009
```


## When it does not fire

 * The project's `LangVersion` is below C# 11: generic attributes do not exist there, and the generic `[Id<T>]` is not emitted.
 * No type of that name is in scope at the attribute (a missing `using` counts), or more than one is.
 * The type is generic (`[Id<Ledger>]` for `Ledger<TKey>` is CS0305) or static (CS0718).
 * The attribute is `[UnionId(...)]`.
