# SIA005 — Redundant `[Id]` attribute

| Severity | Code fix | Applies with `dotnet format` |
|----------|----------|------------------------------|
| Warning  | Yes      | Yes |

Fires at the end of compilation when an explicit `[Id("X")]` says exactly what the member would carry without it. Usually that is the naming convention, but it can also be a member it overrides or implements, the record primary-constructor parameter it was declared with, its wrapper type, or an `[assembly: ExternalId]` mapping — the message says which. The attribute adds nothing, and leaving it in suggests to the next reader that it changes something.


## Example

```cs
public class Customer
{
    [Id("Customer")]                // SIA005: `Id` on `Customer` already infers "Customer"
    public Guid Id { get; set; }
}

public class Order
{
    [Id("Customer")]                // SIA005: `CustomerId` already infers "Customer"
    public Guid CustomerId { get; set; }
}

// SIA005 on the `[property: ...]` half: the parameter's [Id] already tags the property.
public record Change([Id("User")][property: Id("User")] Guid PerformedById);
```

Build output:

```
SIA005: [Id("Customer")] on property 'Customer.Id' is redundant: the naming convention already infers "Customer". Fix: remove the attribute.
SIA005: [Id("User")] on property 'Change.PerformedById' is redundant: the record primary-constructor parameter already carries "User". Fix: remove the attribute.
```

The attribute is quoted as written: a redundant `[Id<Customer>]` is reported as `[Id<Customer>] on property 'Customer.Id' is redundant: ...`.

The reason after `is redundant:` names what supplies the id without the attribute:

| Reason in the message | Source |
|---|---|
| `the naming convention already infers "X"` | The member and type names, including suffix inference when enabled |
| `it already inherits "X" from the member it overrides or implements` | An `[Id]` on the base or interface member |
| `the record primary-constructor parameter already carries "X"` | A `[property: Id(...)]` repeating the parameter's own `[Id]` |
| `its wrapper type already carries "X"` | The member's wrapper type, with `strongidanalyzer.infer_wrapper_ids` on |
| `[assembly: ExternalId] already maps it to "X"` | An external mapping for the member |

For a record, write the tag once, on the parameter. It is the attribute's default target and covers the synthesized property too, so the `[property: ...]` half is the one reported and removed. A `[property: Id(...)]` written on its own also tags the parameter, so either form works on its own; writing both is what gets reported.


## How to fix

Delete the attribute. That is the only fix, and it is safe: the analyzer has already verified the resolved id is identical with and without it.

```
dotnet format analyzers --diagnostics SIA005
```

If the attribute was there to *document* the id rather than to change it, the member name already does that job.


## When it does not fire

 * The explicit value differs from the convention's: `[Id("Person")] Guid Id` on `Customer` is an override, not a redundancy.
 * A base or interface member declares a *different* id. `[Id("Customer")] Guid customerId` on an override whose base says `[Id("Client")]` reads as redundant by name alone, but removing it would inherit `"Client"` and move the mismatch to every call site. The check runs the resolver's full precedence — inherited attributes, the record primary-constructor parameter, the wrapper type, suffix inference, then the name — not the naming rule on its own.
 * Removing it would create an SIA004. When a same-named type declares an untagged `Id`, the explicit attribute is the thing keeping the two domains apart; reporting it would trade one warning for two build errors. See [SIA004](SIA004.md).
 * `[UnionId(...)]` — a union never equals a single convention id.
 * The attribute is what makes the id resolve to that value in the first place. With `strongidanalyzer.infer_suffix_ids` on, `[Id("SourceProduct")] Guid sourceProductId` is only redundant once something *else* vouches for `"SourceProduct"` — a `SourceProduct` type with an `Id` member, or another declaration carrying the same explicit id. The check evaluates the id as if the attribute were already gone; see "Suffix inference and SIA005" in the readme.
 * With `strongidanalyzer.infer_wrapper_ids` on, an attribute on a wrapper-typed member that repeats the wrapper's tag *is* reported — the type supplies the id, so the attribute is redundant.
